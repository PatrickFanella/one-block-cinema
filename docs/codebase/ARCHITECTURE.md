# Architecture

## Current architecture

One-Block Cinema is currently a local-first SwiftUI app shell generated by Rork.

## Entry flow

1. `OneBlockCinemaApp` starts the app.
2. `ContentView` owns the main tab shell.
3. `FilmSessionViewModel` coordinates current session state.
4. Views advance through template/theme selection, prompts, capture/import, assembly, preview/export, and saved sessions.

## Creation flow

1. `HomeView` starts a session from a selected `FilmTheme`.
2. `PromptGenerator` creates a sequence of `ShotPrompt` values.
3. `ShotSequenceView` presents the prompts.
4. `CaptureView` records/imports clips and attaches them to prompts.
5. `AssemblyView` shows the collected clips and edit options.
6. `PreviewExportView` invokes `VideoExportService` for export/share.
7. `SessionStorage` persists saved sessions locally.

## State model

- `FilmSessionViewModel` is the app state hub.
- Session data is modeled by `FilmSession` and `FilmClip`.
- Current persistence is simple `UserDefaults` encoding.
- Future sync should preserve offline-first draft behavior and private-until-publish defaults.

## Integration boundaries

- Media import/capture: iOS Photos/camera APIs.
- Video export: AVFoundation.
- Future backend: auth, sync, profiles, challenges, comments, moderation, age gating.
- Future AI: critique/coach feedback after MVP.

## Known mismatch

The generated UI promises a richer camera/editor/export experience than currently exists. Treat implementation work as productization of a shell, not completion of an existing production app.
